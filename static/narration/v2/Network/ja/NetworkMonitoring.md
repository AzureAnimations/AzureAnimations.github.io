# Network monitoring — ナレーション (ja)

## Step 1 · "It cannot connect"

[calm] ある VM がデータベースに到達できません。
[400ms]
[curious] エラーは出ていませんし、目に見えて落ちているものもありません。それでいて、ブロックしている可能性のあるものが四つもあります。当てずっぽうで進めると、代償が大きくなります。
[500ms]
[confident] ですから、いま自分が本当に投げかけている問いに合わせてツールを分けましょう。Network Watcher は「なぜこの接続がいま失敗しているのか」に答えます。Azure Monitor は「自分のネットワークはこれまで何をしてきたのか」に答えます。

## Step 2 · Network Watcher

[confident] Network Watcher は、稼働中のネットワークを調べるリージョン単位のプラットフォーム サービスです。
[500ms]
[calm] 仮想ネットワークを作成したリージョンでは自動的に有効になります。使い始める前にデプロイするものは何もありません。
[400ms]
[helpful] 本当の価値は、自分がデプロイしたと思い込んでいる内容ではなく、実際の有効な構成を読み取ってくれる点にあります。意図と現実とのあいだにできるこのずれこそ、ネットワーク障害のほとんどが潜んでいる場所です。

## Step 3 · Three tools, in this order

[calm] ここでマイクロソフトは具体的な順序を推奨していて、これは従う価値があります。
[500ms]
[confident] どの手順も次の手順より負担が小さく、たいていの問題は最後までたどり着く前に解決します。
[400ms]
[helpful] まずは IP flow verify から。許可か拒否かを答えるだけでなく、原因となっているルールの名前まで教えてくれるからです。この一つの答えだけで、調査の多くは始まる前に終わります。

## Step 4 · Virtual network flow logs

[confident] フロー ログは、フローごとにメタデータを一行ずつ書き出します。送信元、宛先、ポート、プロトコル、そして許可されたか拒否されたか。
[500ms]
[calm] この記録があるからこそ、先週の火曜日について問いに答えられるのです。
[400ms]
[concerned] NSG flow logs ではなく、VNet flow logs を使ってください。NSG flow logs は提供が終了に向かっています。二千二十五年六月三十日以降は新規に作成できず、既存のものは二千二十七年九月三十日までに移行する必要があります。

## Step 5 · Traffic Analytics

[calm] フロー ログはそれだけでは、何百万行ものデータでしかありません。
[500ms]
[confident] Traffic Analytics はそれを、実際に読める形に集約してくれます。通信量の多い相手、開いているポート、リージョン間のトラフィック、そしてどこでフローが拒否されているか。
[400ms]
[helpful] これには Log Analytics ワークスペースが必要です。Azure Monitor が使うのと同じワークスペースであり、まさにここでネットワークのデータが他のテレメトリと合流し、KQL でクエリできるようになります。

## Step 6 · Connection Monitor

[calm] ここまでのものは、事後に見るか、必要なときに実行するかのどちらかです。
[500ms]
[confident] Connection Monitor は、あるパスをスケジュールに沿って継続的にプローブします。ですから、誰かが気づかなくても、壊れたことが分かります。
[400ms]
[helpful] これが「誰かから報告があった」を「アラートで知らされた」に変えてくれます。SLA が結び付いたパス、たとえばハイブリッド接続や、自分では管理していない依存先には、まさにうってつけのツールです。

## Step 7 · Azure Monitor Network Insights

[confident] Network Insights は、これらすべてを一か所にまとめた Azure Monitor のビューです。
[500ms]
[calm] リアルタイムのトポロジ、すべてのネットワーク リソースの正常性とメトリック、そして診断ツールへの直接のリンクがあります。
[400ms]
[helpful] トポロジ、正常性、メトリックは、設定をいっさいしなくても表示されます。一方、接続とトラフィックのタブは、Connection Monitor とフロー ログを有効にするまで空のままです。ですから、パネルが空なのは「報告することが無い」のではなく、たいてい「有効になっていない」という意味です。

## Step 8 · Which one answers your question

[calm] この二つはポータル上で重なって見えます。混同されるのは、まさにそのためです。
[500ms]
[confident] きれいに切り分ける方法は、自分がどんな問いを持ってやって来たかで分けることです。
[400ms]
[helpful] それに、競合する製品でもありません。Azure Monitor が表示している内容の多くは、Network Watcher が生み出しています。フロー ログと Connection Monitor は Network Watcher の機能であり、そのデータは Log Analytics ワークスペースに届きます。

## Step 9 · Diagnose now, or watch always

[confident] では、押さえておきたい要点です。
[400ms]
[calm] 一方のツール群は、いまこの瞬間になぜ壊れているのかを教えてくれます。もう一方は、これまで何が起きてきたかを教え、次のときには警告してくれます。両方とも必要ですが、有効にするタイミングは違います。
[600ms]
[encouraging] そして、必要になる前にやっておくべきことがひとつ。いますぐ VNet flow logs と Traffic Analytics を有効にしてください。ここで紹介した他のツールは、必要なときに実行できます。この二つだけは、有効にしたあとに発生したトラフィックしか知りません。
