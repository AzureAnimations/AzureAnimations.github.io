# Virtual Network — ナレーション (ja)

## Step 1 · Start With a Virtual Network

[confident] Azure のネットワークは、すべてここから始まります。仮想ネットワークです。
[500ms]
[calm] VNet は、Azure ネットワークの中にある、あなた専用の隔離されたプライベートな領域です。CIDR 表記でアドレス空間を与えます。ここでは、10.0.0.0/16 です。
[400ms]
[helpful] RFC 1918 のプライベート範囲を使いましょう。必要であれば、Azure は IPv4 と IPv6 のデュアル スタックにも対応します。

## Step 2 · Segment It Into Subnets

[calm] 大きなネットワークが一つあるだけでは、設計とは言えません。そこで VNet を、10.0.1.0/24 のような、より小さな範囲であるサブネットに切り分けます。
[500ms]
[confident] 実際の仕事はサブネットで起こります。関連するリソースをまとめ、トラフィックをルーティングする先を与え、セキュリティを適用する境界を与えてくれます。
[400ms]
[helpful] これを覚えておいてください。Azure で配置するすべてのリソースは、サブネットの中に存在します。

## Step 3 · Place a Virtual Machine

[calm] では、中に何か置いてみましょう。サブネットに仮想マシンを配置します。
[400ms]
[confident] ネットワークで通信するには、その VM に少なくとも一つのプライベート IP アドレスが必要です。パブリック IP は任意で、多くの場合は不要です。
[500ms]
[curious] ただし、ここに落とし穴があります。ほとんどの人がつまずくところです。IP アドレスが仮想マシン自体に割り当てられることは、決してありません。

## Step 4 · The NIC Holds the IPs

[confident] そのためにネットワーク インターフェイス、つまり NIC があります。
[400ms]
[calm] 実際にプライベート IP と任意のパブリック IP を保持しているのは NIC です。必要であれば、複数の IP 構成を持つこともできます。
[500ms]
[helpful] NIC は、ちょうど一台の仮想マシンに接続されます。一対一です。その接続が、VM にサブネット上の居場所を与えます。

## Step 5 · Filter Traffic With an NSG

[curious] では、その VM に実際に何が到達できるかを、どう制御しますか。
[400ms]
[confident] ネットワーク セキュリティ グループを関連付けます。NSG は許可と拒否のルールの一覧で、ポート、プロトコル、そして受信と送信という方向で指定します。
[500ms]
[calm] ルールは優先度順に、番号の小さいものから評価されます。NIC に関連付ければ、その一台の仮想マシンのトラフィックをフィルターすることになります。

## Step 6 · One NSG for the Whole Subnet

[curious] では二台目の VM を追加しましょう。三台目も。同じ NSG を、本当にすべての NIC に手作業で関連付けますか。
[500ms]
[confident] もちろん、しません。代わりに NSG をサブネットに関連付けます。
[400ms]
[calm] これでそのサブネット内のすべての NIC が、同じルールを自動的に継承します。仮想マシンをいくつ追加しても、そのまま機能し続けます。

## Step 7 · The Whole Picture

[confident] それでは、全体像をまとめましょう。
[500ms]
[calm] VNet がアドレス空間を与えます。サブネットがそれを分割します。仮想マシンはそのサブネットの中に置かれ、その IP アドレスは NIC 上にあります。VM に直接ではありません。
[400ms]
[calm] そして NSG がトラフィックをフィルターします。一つの NIC に、あるいはスケールさせたいならサブネット全体に関連付けます。
[600ms]
[encouraging] これが Azure ネットワークの中核です。この先で出会う他のすべてのサービスは、まさにこの上に築かれています。
