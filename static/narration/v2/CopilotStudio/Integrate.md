## Step 1 · Why Extend

[confident] On its own, an agent can hold a great conversation. But a great answer often needs a real system.
[600ms]
[calm] The order database, the ticketing tool, an internal API — the agent needs to reach them to actually help.
[600ms]
[impressed] Extending is what turns the agent from "talks about things" into "gets things done" — acting on Contoso's real data.

## Step 2 · Connectors

[confident] The easiest way in: connectors — and Copilot Studio ships with over a thousand, prebuilt.
[600ms]
[calm] They're shared with Power Automate, Power Apps, and Azure Logic Apps — Dataverse, SharePoint, SQL Server, ServiceNow, Salesforce, and hundreds more.
[600ms]
[impressed] Add one as a tool, and the agent can call it mid-conversation — no code. Chances are the system you need already has a connector waiting.

## Step 3 · Custom Connectors

[confident] No prebuilt connector for your system? Wrap any REST API in a custom connector.
[600ms]
[calm] You describe the API — its base URL, auth, and endpoints — then define its triggers and actions, like "StartReturn" or "GetStatus."
[600ms]
[reassuring] Contoso's internal returns API has no prebuilt connector, so a custom one makes it a first-class tool — reusable across the Power Platform, and certifiable to share tenant-wide.

## Step 4 · MCP

[confident] Newer still: add tools from a Model Context Protocol server — MCP.
[600ms]
[calm] In the Tools tab, choose "Add a tool," then "Model Context Protocol." Pick a prebuilt Microsoft MCP connector, or connect your own server by URL.
[600ms]
[impressed] One open standard, many tools — an MCP server can expose both tools AND resources, which is great for custom services, databases, and APIs.

## Step 5 · Agent Flows + Azure

[confident] For heavier, multi-step business logic, back the agent with agent flows and Azure.
[600ms]
[calm] Agent flows for multi-step automation, Azure Logic Apps for enterprise workflows, Power Automate for approvals, Azure Functions for custom code on demand.
[600ms]
[impressed] Low-code meets the full Azure integration stack — the agent can run a real enterprise process, right from a chat.

## Step 6 · Autonomous & Multi-Agent

[confident] And it doesn't have to wait for a chat at all.
[600ms]
[calm] Event triggers let an agent act on its own, and child agents let it delegate to specialists. A new Dataverse row lands, and the Contoso Ops agent fires.
[600ms]
[impressed] It routes to a Reconcile agent to merge duplicates, a Finance agent to handle refunds, a Notify agent to alert the owner — reacting, reconciling, and routing with no human in the loop.

## Step 7 · Recap

[confident] So there's the whole integration surface, in one map.
[600ms]
[calm] Connectors — a thousand-plus, no code. Custom connectors — wrap any REST API. MCP — prebuilt or your own server. Flows and Azure for enterprise logic. And autonomy when you're ready.
[600ms]
[encouraging] Start with a prebuilt connector, and reach for custom connectors, MCP, flows, and autonomy as the need grows. Want to go deeper? The "Extend and manage Copilot Studio agents" path on Microsoft Learn is your next stop.
