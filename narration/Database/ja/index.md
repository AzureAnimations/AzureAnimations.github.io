## Step 1 · Welcome

[confident] AI アプリ向けデータベースのジャーニーへようこそ。
[600ms]
[encouraging] Contoso と一緒に、データベースの選択から構築、検索、最適化まで進みましょう。アーキテクト トラックは任意です。

## Step 2 · One database cannot do it all

[confident] 1 つのデータベースですべては賄えない.
[600ms]
[encouraging] Contoso の AI サポート アシスタントを支える専門チームを紹介し、ジャーニーの道筋と、開発者トラックとアーキテクト トラックの関係を説明します。

## Step 3 · Pick your database for AI apps

[confident] AI アプリ向けのデータベースを選ぶ.
[600ms]
[encouraging] AI ワークロード向けに Azure Cosmos DB for NoSQL と Azure Database for PostgreSQL を比較し、どのトラックを進めるべきか、その理由を理解します。

## Step 4 · Cosmos DB: build and query

[confident] Cosmos DB: 構築とクエリ.
[600ms]
[encouraging] SDK で接続し、項目を操作し、AI アプリ向けにドキュメントを読み取る SQL クエリを書きます。

## Step 5 · Cosmos DB: vector search

[confident] Cosmos DB: ベクトル検索.
[600ms]
[encouraging] 埋め込みを保存し、VectorDistance で結果を順位付けし、メタデータ フィルターとハイブリッド検索を追加し、変更フィードで埋め込みを同期し続けます。

## Step 6 · Cosmos DB: optimize performance

[confident] Cosmos DB: パフォーマンスの最適化.
[600ms]
[encouraging] クエリ パターンを分析し、範囲インデックスと複合インデックスを構成し、ベクトル インデックスの種類を選び、鮮度とコストのバランスが取れる一貫性レベルを選びます。

## Step 7 · PostgreSQL: build and query

[confident] PostgreSQL: 構築とクエリ.
[600ms]
[encouraging] スキーマを設計し、効率的な SQL を書き、Microsoft Entra 認証を使って Python から安全に接続します。

## Step 8 · PostgreSQL: vector search with pgvector

[confident] PostgreSQL: pgvector によるベクトル検索.
[600ms]
[encouraging] pgvector で埋め込みを保存し、距離メトリックを比較し、RAG、セマンティック検索、レコメンデーション向けの取得パターンを構築します。

## Step 9 · PostgreSQL: optimize vector search

[confident] PostgreSQL: ベクトル検索の最適化.
[600ms]
[encouraging] PostgreSQL と pgvector を調整し、ベクトル インデックスを選び、データ レイアウトを設計し、ボリュームに合わせてスケールし、接続をプールします。

## Step 10 · Contoso ships the assistant

[confident] Contoso がアシスタントをリリース.
[600ms]
[encouraging] 1 つのお客様の質問を、チャット履歴、ベクトル検索、注文の検索、チューニングまでたどり、学んだすべてのエンジンがどう役割を果たすかを確認します。

## Step 11 · Design relational data storage

[confident] リレーショナル データ ストレージの設計.
[600ms]
[encouraging] SQL Database、SQL Managed Instance、SQL Server on Azure VMs から選び、スケーラビリティ、可用性、セキュリティを計画します。

## Step 12 · Design data integration and data lake

[confident] データ統合とデータ レイクの設計.
[600ms]
[encouraging] Data Factory、Data Lake、Databricks、Synapse を比較し、ホット、ウォーム、コールドの各パスを計画し、ストリーミング データには Stream Analytics を追加します。

## Step 13 · Choose your next step

[confident] 次のプロジェクトに合ったトラックを選びましょう。
[600ms]
[encouraging] リンク先の Microsoft Learn で実際に手を動かし、別のデータベース スキルが必要になったら、ここに戻ってきてください。
