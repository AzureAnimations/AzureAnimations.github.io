# Virtual WAN — ナレーション (ja)

## Step 1 · The hub you built by hand

[calm] 自分で管理するハブは、スポークが三つくらいなら実にうまく動きます。
[500ms]
[concerned] ところがスポークが三十、リージョンが二つ、支社が四十ともなると、ピアリングとルートテーブルとゲートウェイの世話だけでフルタイムの仕事になってしまいます。
[400ms]
[confident] ここまでに間違いは何もありません。ハブアンドスポークという形は正解です。問題は、そのハブを誰が運用するのかということ。Virtual WAN は、その部分をマイクロソフトが引き受けますという提案なんです。

## Step 2 · Azure Virtual WAN

[confident] Azure Virtual WAN は、接続とルーティングとセキュリティを、マイクロソフト管理のハブ一つにまとめたネットワークサービスです。
[500ms]
[calm] あなたはそこに接続するだけ。中で何が起きるかはマイクロソフトの担当です。
[400ms]
[helpful] できあがる形は、やはりハブアンドスポークです。変わるのは、ハブの中のピアリングとルーティングをマイクロソフトが管理してくれること。別々のリージョンにあるハブどうしの接続も含めて、です。

## Step 3 · What may live in the hub

[calm] virtual hub は、マイクロソフトが作成して管理する仮想ネットワークです。
[500ms]
[confident] そして、これがこの取引のすべてです。ルーティングは手間なく手に入り、その代わり中に好きなものを置く自由は手放すことになります。
[400ms]
[concerned] ここでつまずくチームは多いです。virtual hub の中に VM やドメインコントローラー、Azure Bastion を置くことはできません。それらはスポーク側に置きます。マイクロソフトが virtual hub 拡張パターンと呼んでいるやり方ですね。

## Step 4 · One network, two regions, every branch

[calm] Contoso は、支社の VPN と ExpressRoute 回線、そしてリモートユーザーを、二つのリージョンにあるハブに接続します。
[500ms]
[confident] マイクロソフトがそのハブどうしをつなぎ、その背後にあるすべてのスポークが、互いに到達できるようになります。
[400ms]
[helpful] 二つのハブを結ぶこの線こそ、あなたが決して作らなくていいものです。マイクロソフトが作成して維持してくれる。そしてこれが、二つの地域ハブを一つのグローバルな中継ネットワークに変えてくれるんです。

## Step 5 · Four paths you get for nothing

[confident] Virtual WAN の Standard はフルメッシュです。
[500ms]
[calm] 同じ Virtual WAN に二つのものが接続された時点で、互いに到達できます。同じリージョン内でも、リージョンをまたいでも同じです。
[400ms]
[helpful] 通常のピアリングと比べてみてください。あちらは推移的ではありません。同じハブにピアリングした二つのスポークは、間の何かを指すルートテーブルがなければ、やはり通信できないのです。Virtual WAN では、その経路が最初から用意されています。

## Step 6 · Secured virtual hub

[confident] ハブを secured virtual hub に変えると、Firewall Manager が Azure Firewall をその中に展開します。
[500ms]
[calm] するとそのハブにつながっているすべてのスポークとすべての支社が、共有された一つのファイアウォールで検査されるようになります。
[400ms]
[helpful] そしてここが知っておく価値のあるところ。secured virtual hub にはルーティングが組み込まれています。自分で作ったハブのように、トラフィックを通すためのユーザー定義ルートを書く必要はありません。

## Step 7 · Basic buys almost nothing

[calm] Virtual WAN の SKU は二つあり、その差は決して小さくありません。
[500ms]
[confident] Basic はごく限られた用途のために存在します。Virtual WAN を選ぶような設計は、ほとんどの場合 Standard が必要になります。
[400ms]
[helpful] ハブを二つ以上使いたい、ExpressRoute を使いたい、ポイント対サイトを使いたい、スポーク間の中継がほしい。どれも Standard です。Basic でできるのは、単一のハブへのサイト対サイト VPN まで。そこで終わりです。

## Step 8 · Managed hub, or one you own

[calm] どちらを選んでも、得られる形はハブアンドスポークです。
[500ms]
[confident] 選択の基準は、ハブの中でどれだけの制御が必要かと、そのうちどれだけを自分で運用したいか、その釣り合いです。
[400ms]
[helpful] 本当に決め手になる問いは規模ではありません。ハブの中に自分のものを置く必要があるかどうかです。必要なら、スポークがいくつあろうと Virtual WAN は答えになりません。

## Step 9 · The same shape, someone else's problem

[confident] では、まとめです。
[400ms]
[calm] Virtual WAN は新しいトポロジーを発明するわけではありません。どのみち自分で作っていたはずのハブを引き取って、その運用をマイクロソフトに任せる。中継もリージョン間のリンクも込みで、です。
[600ms]
[encouraging] 判断は一つの問いで決めましょう。ハブの中に置かなければならない自分のものが、何かありますか。ないなら、マネージドを選ぶ。あるなら、自分で作って制御を手元に残しましょう。
