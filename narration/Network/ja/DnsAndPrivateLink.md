# DNS & Private Link — ナレーション (ja)

## Step 1 · A name, and who is allowed to use it

[calm] あなたの Web アプリが必要としているのは、ストレージ アカウント ひとつです。
[400ms]
[curious] 今のところ、アプリはパブリックな名前を問い合わせ、パブリックなアドレスを受け取り、通信はインターネットへ出ていってまた戻ってきます。同じリージョンに並んでいる、たった二つのリソースのためにです。
[500ms]
[confident] これを解決するのは三つの部品で、しかもこの三つはいつも取り違えられます。Azure DNS は名前を世界に公開します。Private DNS は VNet の内側で名前に答えます。そして Private Link は、そのリソースに、答えとして返すためのプライベート アドレスを与えるものです。

## Step 2 · Azure DNS public zones

[calm] パブリック ゾーンは、あなたが所有するドメイン名の権威ホスティングです。
[500ms]
[confident] レジストラーのネーム サーバーを Azure に向ける。それ以降は、あなたのドメインについて世界から届く問い合わせに、Azure が答えるようになります。
[400ms]
[helpful] ここにあるレコードは、見られるためのものです。誰でも、どこからでも問い合わせできる。それがまさに役割です。パブリック ゾーンは、どこをとってもセキュリティ境界ではありません。

## Step 3 · Azure Private DNS zones

[calm] プライベート ゾーンは見た目はほとんど同じで、ひとつだけ決定的な違いがあります。
[500ms]
[confident] そのレコードはインターネットからは解決できません。ゾーンに明示的にリンクした仮想ネットワークからだけ、答えが返ります。
[400ms]
[helpful] このリンクがアクセス モデルのすべてです。リンクしていない仮想ネットワークからは、ゾーンはまったく見えません。部分的に見える、ということも、「ほぼリンク済み」ということもありません。

## Step 4 · Private endpoint

[confident] private endpoint とは、あなたのサブネットの中に置かれ、プライベート IP アドレスを持ち、ある PaaS サービスの特定のインスタンスに結び付いた、ネットワーク インターフェイスです。
[500ms]
[calm] さらに Azure は、そのサービスの名前をそのアドレスに対応付けるレコードを、private DNS zone に書き込みます。だからこの二つは、いつも一緒にデプロイされるのです。
[400ms]
[helpful] ここが本当に新しい部分です。Storage も SQL も、その他のサービスも、ふだんはパブリック エンドポイントの向こう側にいます。private endpoint は、そのうちのひとつをあなたのアドレス空間の中に引き込みます。そして、パブリック アクセスを完全にオフにできるようにします。

## Step 5 · What the lookup actually does

[calm] 名前解決の流れを追ってみましょう。ここでいっきに腑に落ちます。
[500ms]
[confident] アプリケーションは、これまでどおり同じパブリックな名前を使い続けます。Azure はその名前を、静かに privatelink ゾーンへと振り向け、プライベート ゾーンがプライベート IP を返します。
[400ms]
[helpful] だから接続文字列は一度も変える必要がありません。アプリケーションは同じ質問をしている。違うのは答えだけです。

## Step 6 · The link is the whole mechanism

[curious] 完璧なレコードが入ったプライベート ゾーンも、仮想ネットワークがリンクされるまでは、まったく何もしません。
[500ms]
[calm] そしてそのネットワークがカスタム DNS サーバーを使っているなら、リンクだけではまだ足りません。フォワーダーが必要になります。
[400ms]
[confident] もうひとつ、覚えておきたい区別があります。名前を解決できることと、中に入る許可があることは、別ものです。privatelink のチェーンは、どこからでも解決できるように意図的に作られています。問い合わせが成功したという事実が示すのは、そのリソースが存在するということであって、あなたが到達できるということではありません。

## Step 7 · Same shape, opposite purpose

[calm] パブリック ゾーンと、プライベート ゾーン。どちらもレコードの入った DNS ゾーンです。
[500ms]
[confident] 本当に意味を持つのは、すべて、誰に問い合わせる資格があるか、という点です。
[400ms]
[helpful] しかも同じドメイン名を、両方として持つこともできます。いわゆる split-horizon です。質問がどこから来たかによって、返す答えを変えられます。

## Step 8 · It still resolves to a public IP

[concerned] さて、お決まりの失敗です。しかもこれは Private Link で最も多いトラブルです。
[500ms]
[calm] 原因はエンドポイント本体ではなく、ほぼいつも DNS です。そして四つの原因で、そのほとんどが説明できます。
[400ms]
[helpful] 症状には特徴があります。ポータルでは private endpoint が承認済みと表示されているのに、アプリにはパブリック アドレスが返ってくる。あるいは、すでにパブリック アクセスを無効にしたはずのサービスから、四百三 が返ってくるのです。

## Step 9 · Publish, resolve, or reach

[confident] というわけで、要点です。それぞれの部品は、それぞれ違う問いに答えています。
[400ms]
[calm] いま自分がどの問いを立てているのかを声に出して言ってみる。それだけで、選ぶべきサービスはおのずと決まります。
[600ms]
[encouraging] そしてこの二つは、必ず切り分けてください。Private Link のややこしい事故は、ほとんどがこの二つの取り違えから起きています。DNS は、どのアドレスが返るかを決めます。サービスのファイアウォールは、中に入れるかどうかを決めます。
