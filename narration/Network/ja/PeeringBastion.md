# Peering & Bastion — ナレーション (ja)

## Step 1 · Two problems, one afternoon

[calm] きょうは二つの問題を扱います。実はこの二つ、同じ近道を共有しています。
[400ms]
[confident] アプリは一つの仮想ネットワークにあり、データベースは別の仮想ネットワークにあって、お互いが見えません。そして VM にセッションを開きたいとき、いちばん手っ取り早い解決策が、いちばん良くない解決策でもあります。パブリック IP です。
[500ms]
[helpful] どちらの問題にも、同じ「つい選びたくなる答え」があります。そしてどちらにも、十分ほどで用意できる、もっと良い答えがあります。

## Step 2 · Peering joins two networks privately

[confident] ピアリングは二つの仮想ネットワークをつなぎ、それぞれのリソースが一つのネットワークにいるかのように通信できるようにします。
[500ms]
[calm] トラフィックはマイクロソフトのバックボーンの中に留まります。パブリックインターネットも、ゲートウェイも、自分で設定する暗号化も必要ありません。
[400ms]
[helpful] 同じリージョン内でピアリングした VNet 間のレイテンシは、一つの VNet の中と同じです。ピアリング自体が帯域幅の上限を持つこともありません。上限を決めるのは VM のサイズです。

## Step 3 · What peering asks of you

[calm] 要件のリストは短くて、正直なところ、つまずくのはたいてい最初の一つだけです。
[500ms]
[confident] アドレス空間が重なっていてはいけません。アドレス設計をおろそかにしたことが、後からピアリングを作れなくなる最大の原因です。
[400ms]
[helpful] ピアリング済みの VNet のアドレス空間は、ダウンタイムなしでサイズ変更できます。ただし、そのあと両方のピアリングを同期し直す必要があります。それでも、重ならない範囲を最初に計画しておくほうがずっと安く済みます。

## Step 4 · Peering is not transitive

[curious] ここが落とし穴です。A と B をピアリングし、次に B と C をピアリングする。では A から C に届くでしょうか。
[500ms]
[confident] 届きません。通信させたい組み合わせごとに、それぞれのピアリングが必要です。あるいは、あなたが意図して真ん中に置いたルーターが必要になります。
[400ms]
[helpful] ハブアンドスポーク構成でハブに Azure Firewall やネットワーク仮想アプライアンスを置くのは、まさにこのためです。ハブ自身は転送してくれないので、スポーク間のトラフィックに通り道を用意してあげるわけです。

## Step 5 · Now, how do you get in?

[calm] これでネットワークはプライベートになりました。それが狙いでしたね。
[400ms]
[curious] でも、誰かが VM にセッションを開かなければなりません。そして従来からある二つの答えは、どちらも環境全体の安全性を下げてしまいます。
[500ms]
[concerned] 管理のために付けたパブリック IP は、開きっぱなしの扉です。踏み台サーバーも、これから自分でパッチを当て、監視し、守り続けるサーバーが一台増えるということです。

## Step 6 · Azure Bastion is the managed front door

[confident] Azure Bastion は、TLS 経由、ポート四百四十三番で VM への RDP と SSH のセッションを開く、フルマネージドのサービスです。
[500ms]
[calm] 接続元は Azure ポータル、あるいはネイティブクライアントです。VM はプライベート IP のままで、それ以外は何も変わりません。
[400ms]
[helpful] 接続先は VM のプライベート IP です。だから VM にはパブリック IP も、エージェントも、追加のクライアントソフトウェアも要らないのです。

## Step 7 · Four SKUs, four different answers

[calm] 階層は四つあり、それぞれ本当に別の問いに答えています。
[500ms]
[confident] Developer は無料で、サブネットもまったく必要ありません。ただし一度に扱えるのは一台の VM だけで、ピアリングをまたぐこともできません。それより上は、規模と機能の話になります。
[400ms]
[helpful] 選ぶ前に知っておきたいことが二つあります。SKU はダウングレードできません。削除して作り直すことになります。そして、ネイティブの SSH や RDP クライアントに対応しているのは Standard と Premium だけです。

## Step 8 · One bastion, every peered network

[confident] では、二つの考え方が出会うところを見てみましょう。
[400ms]
[calm] Bastion をハブに置き、スポークをそこにピアリングします。そのたった一つのホストから、ピアリングされたどの仮想ネットワークのどの VM にもセッションを開けます。しかも、どれ一つとしてパブリック IP は要りません。
[500ms]
[helpful] アクセスを決めるのは、ネットワーク的に届くかどうかだけではなく、やはりロールの割り当てです。ユーザーには、VM、その NIC、Bastion リソース、そして接続先のネットワークに対する閲覧者ロールが必要です。

## Step 9 · Private reach, and a door you did not build

[confident] では、持ち帰ってほしいポイントです。
[400ms]
[calm] ピアリングは、ネットワーク同士をつなぐプライベートな経路を与えてくれます。Bastion は、そこへ入るためのプライベートな経路を与えてくれます。
[600ms]
[encouraging] そしてもし、管理のためだけに VM にパブリック IP が必要な設計が残っているなら、まず見直す価値があるのはそこです。
