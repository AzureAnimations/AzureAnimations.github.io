## Step 1 · Great code lives outside our repo

[calm] Contoso's weather team wants to reuse code from beyond its own repository.
[600ms]
[concerned] Meanwhile, other teams keep rebuilding the same tools.
[600ms]
[curious] So how can we reuse and share? Let's see how the GitHub community works, and how its ideas help inside a company.

## Step 2 · Open source: share it, and fund it

[calm] Open source code can be used, changed, and shared under its license, and communities build it.
[600ms]
[confident] The benefits are collaboration, transparency, flexibility, and community support.
[600ms]
[optimistic] GitHub Sponsors lets you pay the people who maintain what you rely on, either once or monthly.

## Step 3 · A public repo that welcomes people

[curious] A public repository is open to everyone, who can view and fork it.
[600ms]
[confident] A license, a README, and contribution guidelines show visitors how to use it and join in, and Discussions gives them a place to talk.
[600ms]
[serious] Without a license, default copyright applies, so no one else may reuse the code.

## Step 4 · Make it easy to find

[curious] How do people find a repository? Give it a short description, topics, a README, and a license.
[600ms]
[confident] Topics classify a repo by subject, so it shows up in search, in Explore, and on topic pages.
[600ms]
[calm] Topics use lowercase letters, numbers, and hyphens. You can add up to twenty per repository.

## Step 5 · Contribute with a fork and a pull request

[curious] What if you don't have write access to a project? Fork it to get your own copy.
[600ms]
[confident] Clone it, push your change, then open a pull request so the maintainers can review and merge it upstream.
[600ms]
[reassuring] A fork stays connected to the upstream repository, and you can fork any public repository.

## Step 6 · Fork, template, or clone?

[curious] Fork, template, and clone all copy a repository, but for different jobs.
[600ms]
[confident] Fork to contribute to someone else's project. Use a template to start a new project the same way. Clone to work on a copy locally.
[600ms]
[calm] A fork keeps the commit history, while a repository made from a template starts with a single commit.

## Step 7 · Follow, star, watch: three signals

[calm] Three signals keep you informed. Follow people and organizations to see their public activity in your feed.
[600ms]
[confident] Star a repository to save it and show appreciation to its maintainers.
[600ms]
[curious] Watch a repository to get notifications about it, and you can limit them to events like releases or discussions.

## Step 8 · GitHub Marketplace: extend GitHub

[curious] GitHub Marketplace lists tools that extend your workflow.
[600ms]
[confident] Actions are reusable automations, and apps integrate with GitHub. Some are free and some are paid.
[600ms]
[calm] Anyone can publish an action. Only apps owned by organizations can sell paid plans, after publisher verification.

## Step 9 · InnerSource: open source inside the company

[curious] InnerSource is when a company applies the open source practices to proprietary code.
[600ms]
[confident] Teams make internal repositories visible, accept pull requests from other teams, and document how to contribute.
[600ms]
[reassuring] Private repositories work too. Start with a pilot project, set success criteria, and ask for feedback.

## Step 10 · The GitHub community, inside and out

[calm] Open source gives Contoso code to reuse and a way to give back.
[600ms]
[confident] InnerSource brings the same habits to its own teams.
[600ms]
[proud] This page covers the Explore the GitHub community domain of the G H nine hundred exam. The learning paths below go deeper.
