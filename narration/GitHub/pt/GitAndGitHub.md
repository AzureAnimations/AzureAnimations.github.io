## Step 1 · Without History, Edits Collide

[calm] A equipe de meteorologia da Contoso lança uma API de promoções, e a equipe compartilha um arquivo de promoções.
[600ms]
[concerned] Cópias se acumulam, e uma edição silenciosamente sobrepõe outra.
[600ms]
[serious] Não há história nem forma segura de trabalhar em paralelo. A equipe precisa de uma história compartilhada e de uma forma melhor de trabalhar juntos.

## Step 2 · Version Control Remembers Every Change

[curious] O controle de versões registra o que mudou, quem mudou, quando e por quê.
[600ms]
[confident] Como toda alteração é lembrada, qualquer versão anterior pode ser recuperada.
[600ms]
[optimistic] E isso torna possível o trabalho paralelo, através de ramificações.

## Step 3 · Git Is the Tool, GitHub Is the Platform

[curious] As pessoas confundem esses dois, então vamos separá-los. Git é uma ferramenta de controle de versão distribuída que roda no seu computador.
[600ms]
[confident] GitHub hospeda repositórios Git e adiciona colaboração por cima. Git é open source e funciona bem sem GitHub.
[600ms]
[calm] Empurra, puxe e clone os commits de movimento entre seu computador e GitHub.

## Step 4 · Repository, Commit, Branch

[calm] Três ideias para saber. Um repositório guarda seus arquivos e o histórico de cada um.
[600ms]
[confident] Um commit é um snapshot no tempo, salvo com uma mensagem. Todo commit real tem um autor, um horário e uma mensagem.
[600ms]
[curious] Uma filial é uma área de trabalho separada, mantida separada da principal até você estar pronto.

## Step 5 · Accounts: You, Your Team, Your Company

[calm] Você faz login em uma conta pessoal, com GitHub Free ou GitHub Pro.
[600ms]
[confident] As organizações reúnem equipes, com contas, equipes e funções compartilhadas.
[600ms]
[reflective] Contas empresariais gerenciam muitas organizações, com políticas centrais e faturamento. Os planos mudam, então confira a página de planos da GitHub.

## Step 6 · GitHub Flow: Six Simple Moves

[curious] GitHub fluxo é um fluxo leve, baseado em ramos. Você trabalha em um ramo, pede uma revisão, mescla e depois arruma.
[600ms]
[confident] Primeiro você faz um ramo e faz um commit, o que mantém seu trabalho seguro longe do ramo padrão.
[600ms]
[calm] Depois, um pull request pede feedback, e uma mescagem direciona as mudanças para o principal. Você pode fazer cada movimento no site, na linha de comando ou no GitHub Desktop.

## Step 7 · Review, Merge, Done

[calm] Aqui está o fluxo em ação. Maya abre um pull request da agência dela.
[600ms]
[confident] Ravi revisa e aprova as mudanças. Então o pull request é fundido e a agência é deletada.
[600ms]
[reassuring] Deletar o branch é seguro. O pull request e seus commits permanecem, e o branch pode ser restaurado.

## Step 8 · Markdown Makes Issues and PRs Clear

[curious] O Markdown transforma símbolos em texto simples em títulos, listas, listas de tarefas e código.
[600ms]
[confident] Um sinal at menciona uma pessoa e a notifica. Um hash e um número ligam a um problema ou pull request.
[600ms]
[calm] Funciona em descrições de issues e pull requests, em comentários e em arquivos README.

## Step 9 · Pick the Tool That Fits the Moment

[curious] É o mesmo repositório, mas com portas diferentes: o site, GitHub Desktop, GitHub Mobile, um editor ou a linha de comando.
[600ms]
[confident] GitHub Desktop é um aplicativo gratuito e open source para Windows e macOS, com Git visual e sem comandos para memorizar.
[600ms]
[calm] GitHub Mobile, para Android e iOS, traz notificações, avaliações e comentários para o seu celular.

## Step 10 · Git and GitHub Basics, All in One

[calm] Vamos recapitular. O controle de versões mantém o histórico, o Git é a ferramenta, e GitHub é onde a equipe trabalha junta.
[600ms]
[confident] Você já abordou repositórios, commits, ramos, contas, fluxo GitHub, Markdown e escolher a ferramenta certa.
[600ms]
[proud] Esses são os fundamentos do guia de estudos G H 900, e os caminhos de aprendizado do Microsoft Learn são seu próximo passo.
