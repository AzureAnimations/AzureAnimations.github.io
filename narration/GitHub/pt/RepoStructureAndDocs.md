## Step 1 · A Repo With Only Code

[calm] Priya acabou de entrar na equipe de meteorologia do Contoso, e ela abre o repositório de mapas do tempo. O código está todo lá.
[600ms]
[curious] Mas nada diz a ela qual é o projeto, se ela pode usá-lo, como ajudar, quem revisa as mudanças ou onde relatar uma falha.
[600ms]
[confident] Esse é o problema, e a solução é simples: adicione os poucos arquivos que respondem a essas cinco perguntas.

## Step 2 · Five Files Answer Five Questions

[curious] Cada pergunta tem um lugar, e é apenas um arquivo simples que GitHub sabe como encontrar e mostrar.
[600ms]
[confident] O README diz qual é o projeto e como começar. A licença diz o que as pessoas podem fazer com ela. Contribuir explica como ajudar.
[600ms]
[reassuring] O proprietário do código diz quem revisa, e o arquivo de segurança diz como reportar uma falha. Adicione-os, e ninguém precisa perguntar.

## Step 3 · Where Each File Lives

[calm] GitHub procura em três lugares: a raiz do repositório, uma pasta docs e a pasta oculta do GitHub do Dot.
[600ms]
[confident] Para os donos do README e do código, ele verifica primeiro a pasta Dot no GitHub, depois a raiz, depois o documentos, e a primeira correspondência vence.
[600ms]
[reassuring] Contribuição e arquivos de segurança podem ficar em qualquer um dos três. Mantenha a licença na raiz.

## Step 4 · Start From a Template, Then Add Files

[curious] Um modelo dá a um repositório totalmente novo as mesmas pastas e arquivos em um clique. Você escolhe Usar este modelo e decide se inclui apenas o branch padrão ou todos os branches.
[600ms]
[confident] Isso é diferente de um fork, que mantém toda a história. Um template começa do zero com um único commit.
[600ms]
[calm] Depois disso, um novo arquivo vai para um branch, pronto para um pull request.

## Step 5 · Read the Repo’s Dashboard

[calm] A aba Insights transforma atividade em gráficos. Pulse, colaboradores, tráfego e commits mostram o quão ocupado o repositório está e quem o está usando.
[600ms]
[confident] Padrões comunitários é uma lista de verificação dos arquivos de saúde recomendados, para que você possa ver o que ainda falta.
[600ms]
[impressed] E o gráfico de dependências lista o que o repositório usa, o que usa e quaisquer vulnerabilidades conhecidas.

## Step 6 · Issue, Pull Request or Discussion?

[curious] Existem três lugares para conversar, e cada um tem um trabalho diferente. Escolha pelo que você precisa.
[600ms]
[confident] Um problema acompanha o trabalho, como um bug, uma tarefa ou uma ideia. Um pull request propõe uma alteração, ela é revisada e mesclada.
[600ms]
[reassuring] Uma discussão é aberta: perguntas, ideias, anúncios e enquetes. Se um assunto virar conversa, você pode transformá-lo em discussão.

## Step 7 · Link the Fix to the Issue

[calm] Aqui vai um pequeno hábito que economiza muita arrumação. Coloque uma palavra-chave de encerramento na descrição do pull request, como correções ou fechamentos, seguida do número do problema.
[600ms]
[confident] Quando essa pull request é mesclada ao branch padrão, GitHub fecha o problema para você. Se for mesclada em qualquer outro lugar, a palavra-chave é ignorada.
[600ms]
[reassuring] Para uma edição em outro repositório, adicione o proprietário e o nome do repositório. Você também pode linkar manualmente na barra lateral.

## Step 8 · Templates, Assignments and Filters

[calm] Um repositório ocupado precisa de três pequenas ferramentas, e a primeira é um modelo, que faz com que os problemas cheguem à conclusão.
[600ms]
[confident] Modelos de issue e formulários ficam na pasta de templates de issue do Dot no GitHub, e um template de pull request prepreenche a descrição. Os designados mostram quem é o dono do trabalho.
[600ms]
[impressed] Depois, filtros reduzem a lista. Uma consulta como 'open', rotular bug, designar-me encontra exatamente o que você precisa.

## Step 9 · Watch What Matters

[curious] Você escolhe o quão de perto segue um repositório: apenas participar e menções, toda atividade, personalizada ou ignorar.
[600ms]
[confident] Comentem em uma conversa ou são mencionados, e você se inscreve automaticamente. Tudo chega em uma única caixa de entrada.
[600ms]
[reassuring] Lá você pode marcar itens feitos, salvá-los para depois ou cancelar a inscrição. Notificações não salvas são mantidas por três meses.

## Step 10 · Gist, Wiki or Pages?

[curious] Nem tudo pertence ao README. Escolha a casa pelo trabalho.
[600ms]
[confident] Um resumo é um trecho que é um repositório Git, público ou secreto, e secreto não significa privado. Uma wiki guarda notas longas ao lado do código.
[600ms]
[calm] Pages publica um site estático a partir de um repositório, e os mecanismos de busca podem indexá-lo.

## Step 11 · Three More Helpers for Managing Work

[calm] Algumas ferramentas pequenas estão espalhadas pelo quadro do projeto. Marcos agrupam problemas e pull requests, mostrando porcentagem de conclusão e data de vencimento.
[600ms]
[confident] Respostas salvas são respostas reutilizáveis vinculadas à sua conta, úteis em problemas, pull requests e discussões.
[600ms]
[curious] Insights de projetos mostram os itens de um projeto, agora e ao longo do tempo. O próprio quadro aparece na próxima aula.

## Step 12 · A Healthy Repo, a Working Team

[calm] Os arquivos certos dentro, e as ferramentas certas disponíveis. É assim que um repositório fácil de trabalhar se parece.
[600ms]
[confident] Mantenha a lista de verificação da comunidade verde, faça revisões de rotas com os donos do código, triagem com modelos e filtros, e mantenha cada conversa onde ela deve estar.
[600ms]
[proud] Em seguida, você planeja o trabalho em um quadro de Projetos.
