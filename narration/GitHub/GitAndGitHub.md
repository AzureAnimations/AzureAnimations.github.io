## Step 1 · Without History, Edits Collide

[calm] Contoso's weather team ships a promotions API, and the team shares one promotions file.
[600ms]
[concerned] Copies pile up, and one edit quietly overwrites another.
[600ms]
[serious] There's no history and no safe way to work in parallel. The team needs a shared history and a better way to work together.

## Step 2 · Version Control Remembers Every Change

[curious] Version control records what changed, who changed it, when, and why.
[600ms]
[confident] Because every change is remembered, any earlier version can be recovered.
[600ms]
[optimistic] And it makes parallel work possible, through branches.

## Step 3 · Git Is the Tool, GitHub Is the Platform

[curious] People mix these two up, so let's separate them. Git is a distributed version control tool that runs on your computer.
[600ms]
[confident] GitHub hosts Git repositories and adds collaboration on top. Git is open source and works fine without GitHub.
[600ms]
[calm] Push, pull, and clone move commits between your computer and GitHub.

## Step 4 · Repository, Commit, Branch

[calm] Three ideas to know. A repository holds your files and the history of each one.
[600ms]
[confident] A commit is a snapshot in time, saved with a message. Every real commit has an author, a time, and a message.
[600ms]
[curious] A branch is a separate line of work, kept apart from main until you're ready.

## Step 5 · Accounts: You, Your Team, Your Company

[calm] You sign in to a personal account, with GitHub Free or GitHub Pro.
[600ms]
[confident] Organizations bring teams together, with shared accounts, teams, and roles.
[600ms]
[reflective] Enterprise accounts manage many organizations, with central policy and billing. Plans change, so check GitHub's plans page.

## Step 6 · GitHub Flow: Six Simple Moves

[curious] GitHub flow is a lightweight, branch-based workflow. You work on a branch, ask for review, merge, then tidy up.
[600ms]
[confident] First you branch and commit, which keeps your work safely away from the default branch.
[600ms]
[calm] Then a pull request asks for feedback, and a merge lands the changes on main. You can do each move on the website, the command line, or in GitHub Desktop.

## Step 7 · Review, Merge, Done

[calm] Here's the flow in action. Maya opens a pull request from her branch.
[600ms]
[confident] Ravi reviews it and approves the changes. Then the pull request is merged, and the branch gets deleted.
[600ms]
[reassuring] Deleting the branch is safe. The pull request and its commits stay, and the branch can be restored.

## Step 8 · Markdown Makes Issues and PRs Clear

[curious] Markdown turns plain-text symbols into headings, lists, task lists, and code.
[600ms]
[confident] An at sign mentions a person and notifies them. A hash and a number links to an issue or pull request.
[600ms]
[calm] It works in issue and pull request descriptions, in comments, and in README files.

## Step 9 · Pick the Tool That Fits the Moment

[curious] It's the same repository, but with different doors: the website, GitHub Desktop, GitHub Mobile, an editor, or the command line.
[600ms]
[confident] GitHub Desktop is a free, open source app for Windows and macOS, with visual Git and no commands to memorize.
[600ms]
[calm] GitHub Mobile, for Android and iOS, brings notifications, reviews, and comments to your phone.

## Step 10 · Git and GitHub Basics, All in One

[calm] Let's recap. Version control keeps the history, Git is the tool, and GitHub is where the team works together.
[600ms]
[confident] You've covered repositories, commits, branches, accounts, GitHub flow, Markdown, and picking the right tool.
[600ms]
[proud] These are the basics from the G H nine hundred study guide, and the learning paths on Microsoft Learn are your next step.
