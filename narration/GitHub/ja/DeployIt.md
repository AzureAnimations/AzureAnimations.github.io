## Step 1 · One Pipeline, Two Halves

[confident] 二文字、そしてもう二文字。ひと息に「シーアイ・シーディー」と言われますが、答えている問いは別ものです。
[500ms]
[calm] 継続的インテグレーションが問うのは、*この変更は良いか*。プルリクエストが `ci.yml` を起動し、バックエンドのテスト、フロントエンドのテスト、そして CodeQL のスキャンが走ります。
[500ms]
[serious] そしてすべてが一つの問いにかかります。全部緑か。そうでなければマージは阻止されます。控えるよう促されるのではなく、阻止されます。
[500ms]
[bright] 緑で、しかも変更が main 上にあれば、`cd.yml` が引き継ぎます。イメージをビルドし、GHCR へプッシュし、デプロイし、疎通確認。Azure で稼働です。
[500ms]
[reassuring] 二つの道具ではなく、一つのパイプライン。前半が「よし」と言うまで、後半は決して始まりません。

## Step 2 · Build It Once, Ship the Small Half

[confident] デリバリー側の最初のジョブ。コードを、実行できる形に変えます。
[500ms]
[calm] マルチステージの Dockerfile。ステージ 一 はフルの Node イメージから始まり、開発用も含めてすべての依存関係を入れ、ビルドします。ステージ 二 は軽量イメージから改めて始め、ビルド成果物だけを写し取ります。
[500ms]
[thoughtful] 二段、理由も二つ。実際に動くイメージははるかに小さく、しかも攻撃者が使えるコンパイラーを一つも持ちません。それを生んだコミットのタグを付けて、GHCR へ送られます。

## Step 3 · GitHub Is Not Inside Azure

[serious] さて、皆がつまずくところ。ランナーは GitHub のネットワーク上のマシンです。Azure はそれと面識がありません。
[500ms]
[thoughtful] たぶん直感は*マネージド ID* でしょう。でもマネージド ID は Azure の中で動く何かに付くものです。GitHub のランナーは、そうではありません。
[500ms]
[bright] つまり選択肢は二つ。クライアントシークレットを GitHub に貼り付けて、最悪の瞬間に期限切れになるのを見届けるか。ワークフローにサービスプリンシパルを与え、GitHub 自身のトークンを Azure に信頼させるか。

## Step 4 · Give the Workflow an Identity

[confident] では、サービスプリンシパルとは*何*なのか。三つのものが順番に。
[500ms]
[calm] Microsoft Entra ID のアプリ登録、これが設計図。サービスプリンシパルそのもの、これがあなたのテナントにおけるそのアプリケーションの ID で、Azure が判断の対象にするもの。そして RBAC ロール。Contributor を、サブスクリプションではなく一つのリソースグループに絞って。
[500ms]
[thoughtful] 定義、ID、権限。この三つを分けて考えれば、このモデルは不思議なものではなくなります。

## Step 5 · Deploy Without a Password

[confident] 信頼の仕組みはこうです。
[500ms]
[calm] そのサービスプリンシパルにフェデレーション資格情報を足し、リポジトリを一つ、ブランチを一つ指定します。デプロイ時、GitHub はその実行そのものを示す短命の OIDC トークンを要求し、Entra ID がそれを検証して、Azure のアクセストークンを返します。
[500ms]
[serious] クライアント ID、テナント ID、サブスクリプション ID は今も保存します。どれも機密ではありません。もう保存しないのは、漏れうるパスワード、そして午前三時に期限切れになるパスワードです。
[500ms]
[calm] つまずきやすい細部が一つ。ジョブに id-token write の権限が要ります。なければ GitHub はトークンを発行しません。

## Step 6 · The Job That Actually Releases It

[confident] これがデプロイのワークフローです。
[500ms]
[calm] main へのプッシュで起動します。ブランチ保護があるので、それはマージされたプルリクエストを意味します。id-token write を要求し、production 環境を対象にします。この環境は人の承認を必須にできます。そして Azure Login アクションでサインインします。
[500ms]
[thoughtful] そして*しない*ことに注目してください。決してビルドし直しません。テストがすでに通した、まさにそのイメージをデプロイします。ビルドし直せば、証明したものとは別の成果物になってしまいます。

## Step 7 · From a Rainy Afternoon to Running Code

[warm] さて、いちばん最初まで戻りましょう。
[500ms]
[calm] 雨が静かに Contoso の売上を削っていました。それがビジネスケースになり、四つのエピックになり、ボード上のサブタスクになり、ブランチになり、プルリクエストになりました。テストとスキャンで証明され、小さなイメージに梱包され、パスワードを一つも保存しないサービスプリンシパルによってデプロイされました。
[500ms]
[reassuring] どの手順も特別なものではありません。これを成り立たせているのは、そのすべてが毎回、誰かが思い出して頼まなくても走る、ということです。
