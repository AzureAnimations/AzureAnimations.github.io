## Step 1 · Not Autocomplete. A Pair Programmer.

[warm] ボードは埋まりました。誰かが実際にコードを書かなければなりません。そして、あなたは一人で書くわけではありません。
[500ms]
[calm] 左は普通のオートコンプリート。入力すると、ファイル内ですでに見た単語を提示します。右は Copilot。何をしたいかをコメントで書くと、関数を書いてくれます。
[500ms]
[thoughtful] 違いは賢さではなく、文脈です。ただしこれは提案エンジンであって神託ではありません。時間を本当に節約できる程度には当たり、毎行読む必要がある程度には外します。

## Step 2 · What Is Free, and What You Pay For

[calm] Copilot Free は無料で、実用に足ります。月に二千回の補完、モデルは AI が選びます。含まれないのはクラウドエージェントです。
[500ms]
[bright] Pro は月十ドルで AI クレジット千五百。Pro Plus は三十九ドルで七千とプレミアムモデル。Max は百ドルで二万。職場では席単位で、Business が十九ドル、Enterprise が三十九ドルです。
[500ms]
[reassuring] そして学生や教職員なら、支払う前に手を止めてください。GitHub の認証を受ければ Pro が無料になります。

## Step 3 · AI Credits: What Actually Costs You

[bright] ここが多くの人の誤解しているところです。コード補完、つまり入力中に現れる灰色の文字は、クレジットをまったく消費しません。有料プランなら無制限なので、一日中コードを書いてもメーターは動きません。
[500ms]
[serious] 動かすのはこちら。チャットのメッセージ、エージェントの実行、そして Copilot によるコードレビュー。考える処理であり、それぞれが月ごとの残量から引かれます。
[500ms]
[thoughtful] 使い切ると追加クレジットは一つ一セントですが、職場のアカウントでは、それを有効にするかどうかは管理者が決めます。

## Step 4 · Who Picks the Model

[confident] Copilot は単一のモデルで動いてはいません。複数のベンダーによる入れ替わるラインアップの上で動きます。そして私は意図的にどれも名前を挙げません。そのリストは来四半期には古くなっているからです。
[500ms]
[calm] 変わらないのは、誰が選ぶかです。Free と Student では選択肢は一つ、Auto。GitHub が選び、しかもよく選びます。Pro と Business ではモデル選択が使え、Pro Plus、Max、Enterprise ではプレミアムモデルも含まれます。
[500ms]
[thoughtful] 大きいモデルが自動的に良い答えになるわけではありません。まずは Auto から。

## Step 5 · Copilot in VS Code

[confident] では実際に使ってみましょう。VS Code に GitHub Copilot 拡張機能をインストールし、プランを持つアカウントでサインインして、チャットを開く。準備はこれだけです。
[500ms]
[calm] ここにあるのはサブタスク 一 点 一、ベースとなるサーバーです。チャットに何が打ち込まれるかに注目してください。「サーバーを書いて」ではなく、実際の要件です。まず backend のソースを読むこと。設定を読み込むこと。変数が欠けていたら直ちに失敗すること。設定されたポートで待ち受けること。SIGINT と SIGTERM で綺麗に終了すること。
[700ms]
[serious] そして働く順番を見てください。先に書きません。読みます。ソースフォルダー、続いて app ドット js と設定ファイル。エクスプローラーで順に光っていきます。それから声に出して考えます。app ドット js はすでに Express アプリをエクスポートしている、だから server ドット js が持つべきなのはルートではなくプロセスだ、と。
[700ms]
[bright] そのあとで初めて書きます。server ドット js の二十行、そのすべてが、いま読んだプロジェクトに収まっています。推測する道具と、見てから書く道具の違いがここにあります。

## Step 6 · Ask, Plan, Agent

[confident] チャットは一つのものではありません。同じ Copilot が三つの異なる仕事をしています。
[500ms]
[calm] Ask は質問に答えるだけで、ディスク上は何も変えません。Plan は読み取り専用のツールでリポジトリを読み、実装計画を書きます。提案するのは Plan、承認するのはあなたです。Agent は実際に作業します。ファイルを編集し、コマンドを実行し、自分のエラーを読んで再試行します。
[500ms]
[reassuring] そしてこれらはつながります。計画を終えると Start Implementation というボタンが現れ、そのままエージェントに引き渡せます。

## Step 7 · Hand Sub-task 1.2 to the Coding Agent

[confident] Copilot が働く場所がもう一つあります。それはあなたのノートパソコンではありません。
[500ms]
[calm] github ドット com に戻ると、ボード上の次のイシュー、サブタスク 一 点 二 があります。
[500ms]
[bright] 右側の Assignees を見てください。二つ目のボタン、Assign to Agent があります。この一つのボタンが引き渡しのすべてです。押せば Copilot が担当者になります。
[500ms]
[calm] セッションはあなたのマシンではなく GitHub のインフラで始まります。ふたを閉じて離れて構いません。一分ほどで、ドラフトのプルリクエスト十四番が開きます。
[500ms]
[thoughtful] ただし、このイシューは曖昧な一行ではありません。受け入れ条件が三つ、Azure Maps のキーを決して漏らさないことまで書かれています。ボードに書いたものが、そのままプロンプトなのです。

## Step 8 · You Get a Draft, Not a Decision

[confident] そして返ってくるのがこれです。Draft と付いたプルリクエスト。三つのファイル、テスト込み。
[500ms]
[serious] 重要な言葉は Draft です。とても速い同僚からの提案であって、近道は一切与えられません。差分を読み、ブランチを取得し、実行してください。
[500ms]
[thoughtful] 行を書いたのは Copilot ですが、記録上の作者はあなたです。マージにはあなたの名前が載ります。そして午前二時に壊れたときの障害報告にも。
[500ms]
[bright] そこで次の問いが出てきます。このコードは、そもそもどのブランチにいるべきだったのか。
