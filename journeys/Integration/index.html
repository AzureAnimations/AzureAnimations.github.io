At a glance

Four brokers, four different jobs

Queue Storage, Service Bus, Event Hubs and Event Grid all move data between programs, but they carry different things. Start with what you are sending, pick the job you need done, then compare the details side by side.

First, what are you sending?

A message

Data the sender expects someone to act on, such as “process order 1042”.

Queue StorageService Bus

A discrete event

A lightweight notice that something changed. The publisher does not care who reacts.

Event Grid

An event stream

A continuous, time-ordered series of readings that you analyse together.

Then, what do you need to do?

Carries messages · tasks

Azure Queue Storage

A simple, very large backlog of work inside a storage account. Producers add tasks; workers poll, lease a message, process it, then delete it.

Choose it when

  • You need a low-cost buffer to absorb a traffic spike
  • The backlog might grow beyond 80 GB
  • A worker should save progress on the message itself

Watch out: No guaranteed order, no duplicate detection and no built-in dead-letter queue. Track the dequeue count; the Functions queue trigger moves repeat failures to a -poison queue.

Carries messages · transactions

Azure Service Bus

An enterprise broker with queues, and topics that give each subscription its own copy. With peek-lock, a receiver settles a message only after the work succeeds.

Choose it when

  • Order matters: sessions give FIFO per SessionId
  • You need duplicate detection, transactions or dead-lettering
  • Several systems each need their own copy of a message

Watch out: Messages are up to 256 KB on Standard and up to 100 MB on Premium. A queue or topic holds 1–80 GB, so it is not a bottomless backlog.

Carries an event stream

Azure Event Hubs

A partitioned, append-only log built for millions of events. Each consumer reads from its own offset and can rewind within the retention period.

Choose it when

  • Telemetry, clickstreams or logs arrive continuously at high volume
  • Several apps must read the same stream independently
  • You want a Kafka endpoint or automatic archiving with Capture

Watch out: Order is kept only within a partition, and there is no dead-letter queue. Each consumer checkpoints its own position.

Carries discrete events

Azure Event Grid

A serverless event router. A source announces that its state changed; Event Grid filters the event and pushes it to every matching handler.

Choose it when

  • Code should react the moment a resource changes, such as BlobCreated
  • You need fan-out with filters on event type or subject
  • You want MQTT or pull delivery through Event Grid namespaces

Watch out: An event is a notice, not a work queue: up to 1 MB and no ordering. The default retry policy is 30 attempts or 24 hours; configure a dead-letter location or undelivered events are dropped.
